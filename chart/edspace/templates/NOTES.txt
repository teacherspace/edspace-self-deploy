{{- if or .Values.secrets.setupToken (and .Values.secrets.autoGenerate (not .Values.secrets.existingSecret)) }}

First-run setup (fresh database only) — create the first platform admin at:
  https://{{ .Values.ingress.host | default .Values.app.host }}/setup?token=$(kubectl -n {{ .Release.Namespace }} get secret {{ include "edspace.fullname" . }}-generated -o jsonpath='{.data.setup-token}' | base64 -d)
  The link is valid for 7 days from the token's issue time and stops working
  once a platform admin exists. Expired? Mint a new one:
    helm upgrade {{ .Release.Name }} <chart> --reuse-values \
      --set secrets.setupToken="$(date -u +%Y%m%d%H%M%S).$(openssl rand -hex 16)"
{{- else }}

First-run setup (fresh database only): set EDSPACE_SETUP_TOKEN via envSecret
and open https://{{ .Values.ingress.host | default .Values.app.host }}/setup?token=<value>,
or seed the admin with EDSPACE_PLATFORM_ADMINS (see docs/configuration.md).
{{- end }}

{{- if and .Values.secrets.autoGenerate (not .Values.secrets.existingSecret) }}

WARNING - generated secrets are in use.
  SECRET_KEY_BASE / TOKEN_SIGNING_SECRET / RELEASE_COOKIE were generated on
  first install and are kept in Secret {{ include "edspace.fullname" . }}-generated.
  Retrieve them:
    kubectl -n {{ .Release.Namespace }} get secret {{ include "edspace.fullname" . }}-generated -o yaml
  For production or GitOps (Argo/Flux renders without cluster access and
  would rotate them!) set secrets.* values or secrets.existingSecret.

{{- if .Values.db.bundled.enabled }}

WARNING - bundled Postgres is for evaluation only.
  Single node, no backups, no replication. Point db.* at a managed
  Postgres (>= 16.3 with vector/citext/pg_trgm) before production use.
  On first install migrations run at app boot; from the next upgrade on,
  they run in a pre-upgrade Job.
{{- end }}
